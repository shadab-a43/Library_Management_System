# Library_Management_System
A college project developed in Python to manage library books and basic library operations.

## Day 1 – Python Basics

### Topics Covered

- Variables
- Data types
- Boolean values
- Lists
- Conditional statements
- For loop

### Work Completed

- Created basic book information.
- Stored book title, price, availability, and category.
- Checked book availability using an `if-else` statement.
- Created a list containing five library books.
- Displayed the library books using a loop.

### Concepts Learned

- Variables store data.
- Lists store multiple values.
- Conditions are used for decision making.
- Loops are used to process multiple items.

✅ Completed


## Day 2 – Functions & OOP Classes

### Topics Covered

- Functions
- Parameters and return values
- Recursive functions
- Classes and objects
- Constructors
- Destructors
- Methods

### Work Completed

- Created a function to calculate book fines.
- Created a recursive function to calculate GCD.
- Created a `Book` class with book details.
- Created an `issue()` method to change book availability.
- Created a `Member` class with name and email.
- Used a constructor to initialize member details.
- Used a destructor to understand object destruction.

### Concepts Learned

- Functions make code reusable.
- Recursion allows a function to call itself.
- Classes are blueprints for objects.
- Constructors initialize objects.
- Destructors run when objects are destroyed.

## Day 3 – OOP Advanced Concepts

### Topics Covered

- Encapsulation
- Inheritance
- Polymorphism
- Abstraction

### Work Completed

- Used private data for encapsulation.
- Created `LibraryBook` and `EBook` classes for inheritance.
- Demonstrated polymorphism using the same method with different behavior.
- Created an abstract `LibraryItem` class.
- Implemented an abstract method using a child class.

### Concepts Learned

- Encapsulation protects internal data.
- Inheritance allows code reuse between classes.
- Polymorphism allows the same method to have different behavior.
- Abstraction hides unnecessary implementation details.
